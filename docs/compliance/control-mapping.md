# Control Mapping

Written 2026-10-08 against branch `improve/2026-10-08`. Re-verified against the code on 2026-10-08 (see `verification-log-2026-10-08.md`).

> **Disclaimer.** This is a control mapping and evidence index, not a certificate, an audit report or an
> attestation. The project holds no certification and has not been audited against ISO/IEC 27001, SOC 2,
> the NIST AI RMF or any other framework. The framework column gives loose theme names only, to help a
> reviewer find the area; it does not claim that any requirement of any framework is met. The project is a
> hackathon prototype for synthetic documents (`SECURITY.md`).

Status words: **IMPLEMENTED** = code plus a test or direct code read back it; **PARTIAL** = part of the
objective is met and the gap is stated; **GAP** = not provided. Every IMPLEMENTED or PARTIAL row cites
code or a test that was opened for this index. Evidence is cited by file plus symbol (function, constant,
route string) or by test file plus test title; if a symbol moved, `grep -rn '<symbol>' *.js` finds it.
"SOC 2" below means the Trust Services Criteria themes; "AI RMF" means the NIST AI RMF function names
(Govern, Map, Measure, Manage).

| 1 | Identity and authentication | Bearer tokens of 32 random bytes (`scripts/setup-local.mjs` `crypto.randomBytes(32)` for the `<id>.token` files; `directory-admin.js` `changeDirectory()` for `person.create` and `person.rotate`). Only SHA-256 hashes (`tokenHash`) are stored and compared with `timingSafeEqual` in `access-control.js` `authenticate()`, which accepts only `Bearer` plus 32 to 256 URL-safe characters. The registry is re-read on every request (`server.js` `routeApi()` calls `loadAccess()` from `access-control.js`), so disabling a person or a department takes effect on the next request (`registry-schema.js` `principalEnabled()`). Failed sign-in throttle: `auth-throttle.js` `createAuthThrottle()`, configured by `throttleFromEnv()` from `AUTH_MAX_FAILURES`, `AUTH_WINDOW_SECONDS`, `AUTH_LOCK_SECONDS`; defaults 10 failures / 60 s window / 60 s lock. The lock is checked before authentication (`authThrottle.check()` in `server.js` `routeApi()`), so a locked client gets 429 even with a valid token. The throttle key is the client address: IPv4 as written, IPv6 reduced to its /64 (`auth-throttle.js` `addressKey()`).
